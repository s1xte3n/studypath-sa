**Research date:** 2026-10-21  
**Scope:** Planned Azure hosting/integration services for StudyPath SA; local-only application today.  
**Status:** Official documentation reviewed; actual StudyPath Azure settings remain unverified.

## Executive result

Microsoft documentation confirms that Azure services expose several distinct logging and telemetry planes. Some records are generated by default (notably Azure Activity Log and platform metrics); other resource logs require diagnostic settings; application monitoring can be enabled separately; and retention depends on the specific service, destination, workspace/table settings, and configuration. Therefore, “Azure default logging” is not one setting or one retention period.

The repository currently has no deployed Azure resources or deployment configuration available for inspection. No actual StudyPath request logs, diagnostic settings, Application Insights resource, Log Analytics workspace, storage lifecycle policy, Entra tenant log configuration, or AI-service abuse-monitoring configuration was inspected. **Do not mark provider verification complete.**

## Privacy-preserving configuration requirements before deployment

1. **Inventory exact resources and processors.** Record service name/SKU, region, public endpoints, custom domain/DNS/CDN, API gateway, functions, data stores, identity, AI services, monitoring destinations and CI provider.
2. **Default to no optional content capture.** Disable optional analytics and request/response body or prompt/completion logging; avoid detailed trace levels in production. Where diagnostics are required, collect the minimum categories necessary for security and operations.
3. **Minimise sensitive fields.** Never log learner names, marks, subjects, profile content, uploaded documents, application-tracker content, tokens, cookies, authorization headers, prompts or response bodies. Avoid query strings containing learner data. Configure redaction and verify it in captured records.
4. **Constrain access.** Use least privilege for logs/workspaces/storage, restrict exports, protect credentials with managed identities/Key Vault as applicable, and audit access to log destinations.
5. **Set retention deliberately.** Record exact retention for each source and copy/destination, including tables, storage lifecycle, backups/soft-delete and exports. A source's retention does not automatically govern exported copies.
6. **Review terms and location.** Read the current official terms/service-specific privacy documentation for the exact SKU, region and feature; document any external processors, cross-region processing and unresolved legal/privacy questions.
7. **Verify deployed behaviour.** After approved deployment, run synthetic-only probes and inspect actual request/log/telemetry destinations. Confirm that sensitive test markers do not appear in URLs, request/response bodies, logs, traces, Application Insights, storage, database query logs, APIM diagnostics or AI monitoring. Keep evidence redacted.
8. **Reassess changes.** Repeat the review when services, SDKs, diagnostic settings, regions, data flows or features change.
