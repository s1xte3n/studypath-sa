# ADR-005 — Privacy-Preserving Observability and Recovery

- **Status:** Proposed; provider/runtime-specific choices open.
- **Date:** 2026-10-16
- **Requirements:** NFR-REL-001, NFR-PRV-001, NFR-DATA-001, NFR-PERF-001.
- **Related:** OR-005, OR-013, Q-005, Q-009, Q-012.

## Context
The application must be diagnosable without exposing learner marks, interests, eligibility results, tracker notes or other profile data. Runtime monitoring can also incur cost and capture request data by default.

## Decision
Use allowlisted technical telemetry only if and when a runtime is approved. Permitted fields: timestamp, environment/service, route template, status/error code, duration, generated correlation ID, build/catalogue version, dependency outcome. Prohibit request/response bodies, raw query strings, profile values, tokens and learner-linked recommendation data. No analytics/session replay by default in the current local demo.

Measure catalogue freshness/provenance, API latency/error rate if an API exists, golden-set false-positive ELIGIBLE count, CI/deployment outcomes and cost. Alert thresholds, retention, owners and numeric SLO/RTO/RPO remain unapproved until service choices and operational responsibilities are frozen.

## Alternatives considered
1. Capture all request/response bodies for debugging: rejected due to privacy risk.
2. Add analytics/session replay to understand behavior: deferred; not required and creates collection risk.
3. Set numeric availability promises without chosen hosting: rejected as unsupported.
4. Rely only on platform defaults: rejected until actual fields, access and retention are inspected.

## Trade-offs and consequences
- Allowlisted telemetry can make some debugging slower, but reduces accidental exposure.
- Golden-set correctness is a release signal independent of production user telemetry.
- Monitoring services and retention contribute to the R100/month cap and must be costed.
- Recovery targets remain qualitative until a persistent/runtime service is selected.

## Gate
Inspect dependency telemetry, browser network/storage, provider logs and retention; test API timeout/schema/stale-data behavior; assign alert/incident owner; approve cost and recovery objectives before public deployment.
