# ADR-004 — Infrastructure, Environments and R100/Month Cost Gate

- **Status:** Proposed; no Azure provisioning authorized.
- **Date:** 2026-10-16
- **Requirements:** NFR-SEC-001, NFR-REL-001, NFR-PRV-001; D-003, D-004, D-047.
- **Related:** Q-003, Q-004, Q-009, OR-019.

## Context
The supplied specification documents Azure Static Web Apps, API Management, Functions, PostgreSQL, Blob Storage, Entra External ID, AI services, Key Vault, Application Insights, Terraform and GitHub Actions. Current scope and budget do not justify treating every listed component as mandatory. Total spend is capped at R100/month and the current demo is local.

## Decision
Use local synthetic demo as the immediate target. Treat Static Web Apps, Functions, and API Management as candidates for later API deployment; evaluate whether API Management is necessary. Do not introduce PostgreSQL, Blob Storage, Entra External ID, Azure OpenAI or Document Intelligence into the initial journey. No cloud resource may be provisioned until exact service/plan/region/quotas, total cost/overages, access, deployment owner, secrets, telemetry retention, rollback and budget controls are approved.

Use Terraform for approved infrastructure changes and GitHub Actions for reproducible validation/deployment only after their repository presence and permissions are inspected. Separate environment configuration and synthetic data; no production data in development/staging.

## Alternatives considered
1. Provision the entire documented Azure baseline immediately: rejected due to scope, budget and unresolved operational decisions.
2. Use Static Web Apps only with no API: lower cost but conflicts with D-044 API-first direction if used as the final architecture; may still host the current local/static demo.
3. Use Functions without API Management: potentially cheaper/simpler; needs threat, quota, routing and governance review.
4. Use Functions plus API Management: clearer gateway policy boundary but potential cost/complexity; must justify against R100 cap.

## Trade-offs and consequences
- Local-first demo minimizes cost and operational risk.
- API-first intent is preserved without pretending runtime details are frozen.
- Cloud architecture remains deliberately conditional until resource-by-resource cost and quota evidence is reviewed.
- Availability, backup and recovery objectives cannot be promised until service choices are made.

## Gate
A resource inventory and current price/usage estimate, private billing review, subscription permissions, provider region/quotas, IaC state backend and deployment rollback plan are required before provisioning.
