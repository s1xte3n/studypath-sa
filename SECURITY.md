# Security Policy

## Reporting a vulnerability
This is a private project repository. Do not publish credentials, personal information or exploit details in public channels. Report suspected vulnerabilities directly and privately to the repository owner/team using an agreed private contact channel. The project has not yet designated a separate security contact or response SLA; that is an open governance item.

Include a concise impact description, affected component, reproduction steps where safe, and any suggested mitigation. Do not access, copy or disclose other people's data while investigating.

## Sensitive data rules
- Do not commit secrets, API keys, access tokens, private keys, certificates or populated environment files.
- Keep local configuration containing credentials out of version control.
- Use synthetic learner data for development and demonstrations.
- Do not place real learner data or credentials in issues, pull requests, logs, screenshots or test fixtures.
- Minimise collected learner information and establish approved privacy, retention and deletion practices before processing real records.
- Eligibility decisions must use deterministic rules and verified requirements; AI output is not an authority for admission or funding.

## Current limitations
This policy is a baseline, not a security audit or compliance certification. Authentication, authorization, storage, incident response, vulnerability handling, backup and deployment controls must be designed and tested before release.
